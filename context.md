# NorAI — Project & Rebuild Context

## 1. Project Overview
**NorAI** is an automated educational processing pipeline that converts raw lecture videos and audio into structured, multi-modal study materials:
- **Comprehensive Study Notes** (`.md` with formulas, diagrams, OCR, and concepts)
- **Revision Notes / Cheat Sheets** (concise exam takeaways and core concept breakdowns)
- **Quiz Assessments** (MCQs, short answer, conceptual questions)
- **Flashcards** (automated 0-call JSON transformation from assessments)
- **AI Chat Tutor** (RAG-based conversational assistant)

---

## 2. Rebuild Roadmap & Progress Status

### Tier 0: Concurrency & Performance ✅
- Audio transcription and chunking run concurrently with video keyframe extraction and scene detection.

### Tier 1: Model Migration & Schema Enforcement ✅
- Migrated all LLM endpoints to `gemini-3.1-flash-lite`.
- Enforced strict Pydantic `response_schema` across all JSON-generating calls.

### Tier 2: Latency & Cost Optimization (Current Phase)
- **Task 2.0 (Files API Parallelization)**: Concurrently uploads screenshot candidate batches using `ThreadPoolExecutor`.
- **Task 2.1 (Chapter Visual Batching)**: Replaced ~40 per-chunk visual LLM calls with chapter-aligned batch calls (1 call per chapter).
- **Task 2.3 (Consolidated Chapter Artifacts)**: Combined study notes, revision notes, and quiz assessments into 1 consolidated LLM call per chapter (0-call flashcard derivation).

| 2 | `notes/notes_generator.py` | `NameError: name 'types' is not defined` | Missing SDK import for `types.GenerateContentConfig`. | Added `from google.genai import types`. |
| 3 | `visual/visual_extractor.py` | `NameError: name 'create_empty_visual_object' is not defined` | Fallback function referenced on missing/failed visual objects but not written. | Defined `create_empty_visual_object(chunk_mapping)`. |
| 4 | `visual/visual_extractor.py` | `NameError: name 'ChapterVisualKnowledgeModel' is not defined` | Pydantic response schema class referenced in LLM call but omitted. | Defined `ChapterVisualKnowledgeModel` with `visual_objects: list[VisualObjectItem]`. |
| 5 | `notes/screenshot_selector.py` | Screenshot Pass 1 & Pass 2 URL Hallucination | Gemini Flash-Lite returned synthetic URLs (e.g. `https://storage.googleapis...`) instead of local paths, causing 100% frame rejection. | Added schema `Field(description=...)` hint and positional list remapping fallback in `score_frames_batch()` and `parse_selection()`. |
| 6 | `visual/visual_extractor.py` | Silent skip of all visual processing | `process_all_chunks()` looked for `"chunk_ids"` list, but outline chapters define ranges via `"start_chunk"` and `"end_chunk"`. | Derived range `list(range(start_chunk, end_chunk + 1))` when `"chunk_ids"` is absent. |

| 8 | `notes/screenshot_selector.py` | Missing `Field` import & `random` module reference bug | `Field` used without import (`NameError`), and `random.uniform()` called on imported `random` function object (`AttributeError`). | Updated imports to `from pydantic import BaseModel, Field` and `import random`. |
| 9 | `visual/visual_extractor.py` & `notes/screenshot_selector.py` | Duplicate Frame Uploads & Remapping Shift | Shared fallback keyframes appended per-chunk without deduplication caused duplicate Files API uploads & risk of index-based remapping shift. | Added canonical `dedup_paths()` helper, path deduplication before upload, filename-based remapping with collision guard. |

## 4. Current Standing & Architecture Rules

1. **Pipeline Execution Order**:
   1. Stage 1–4: Concurrent Audio Transcription + Video Keyframe Extraction & Scene Detection.
   2. Stage 5: Text Knowledge Extraction (per-chunk parallel).
   3. Stage 6: Lecture Outline Generation & Chapter Clustering.
   4. Stage 7: Chapter-Aligned Visual Extraction (Task 2.1 — 1 call per chapter).
   5. Stage 8: Keyframe Screenshot Mapping & Selection.
   6. Stage 9: Knowledge Merging (combines text + visual objects per chunk).
   7. Stage 10: Chapter Building & Consolidated Artifact Generation (Task 2.3 — 1 call per chapter).
2. **Schema & Fallback Guarantees**:
   - Every LLM endpoint uses Pydantic `response_schema`.
   - Every stage implements 3-retry graceful degradation writing fallback output with `"incomplete": true`.
   - Screenshot paths use positional list alignment if the LLM echoes synthetic strings.
